# Authentication

Internal `users.id` is the owner of community records. `auth_identities` links email/password, Google, and historical `chatgpt` provider IDs without changing ownership. The PostgreSQL import preserves IDs, PBKDF2-HMAC-SHA-256 password hashes (310,000 iterations), token hashes, and session hashes. No forced password reset or static signing secret is needed.

Registration creates user, password identity, profile, and verification token in one transaction. Verification and password reset consume one-time hashed tokens with their account updates in a transaction. Sessions use random opaque tokens in an HttpOnly, SameSite=Lax, Path=/ cookie. Production cookies are Secure and host-only with a `__Host-` prefix; local development uses a non-Secure local cookie. Session tokens are hashed in the database, expire after 30 days, can be revoked, and are capped at 12 active sessions per account. Verification expires in 60 minutes, reset in 45 minutes.

Google sign-in uses Authorization Code + PKCE, state, nonce, Google JWKS signature verification, issuer/audience/verified-email validation, and safe relative return paths. `GOOGLE_REDIRECT_URI` must use the web origin and `/api/auth/google/callback`. The Next proxy passes OAuth cookies and allows the Google authorization redirect. Existing unverified email identities are revoked before verified Google ownership is linked. New Google users must complete their profile.

Historical hosted-platform identities remain in `auth_identities`, but the public API never authenticates from caller-provided `oai-authenticated-user-*` headers. The proxy and API strip those headers. A legacy account needs an existing valid session or a safely linked verified email/Google identity; no trusted hosted-identity adapter is deployed. Legacy-only accounts with no independently verified login method therefore cannot sign in after cutover yet. This blocks a release that promises continued access for every existing user; see the final audit. The profile completion and moderation rules still use internal account IDs. Configure `ANIME_CLASH_ADMIN_USER_ID` to the migrated admin user ID.

Mutation routes check same-origin `Origin`/Fetch Metadata and enforce ownership and role checks. CORS allows only `APP_BASE_URL`; the API uses its direct client IP, without trusting arbitrary forwarded headers. Authentication requests have database-backed rate limits. Never enable `AUTH_DEV_EMAIL_LOG` in production: in local development it can print verification/reset URLs. Production needs Resend `RESEND_API_KEY` and `EMAIL_FROM` for email delivery.

The fixture flow exercises registration, verification, login, authenticated API, logout and revocation; Google provider integration must be checked with real staging credentials and registered callback URLs before cutover.
